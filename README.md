A diferença entre Branch, Merge e Pull Request

Integrantes: Felipe Pericles Sousa, Cristiano Miguel Veloso e Sávio Luiz Campos

Perguntas:
1. Explique a Diferença entre Branch, Merge e Pull Request

Branch, merge e pull request são conceitos fundamentais no uso do Git, especialmente em projetos colaborativos. Um branch (ramo) é uma ramificação do código principal que permite desenvolver novas funcionalidades, corrigir bugs ou testar ideias sem interferir diretamente no código estável, geralmente mantido no branch principal. O merge é o processo de unir as alterações feitas em um branch em outro. 
O pull request é uma solicitação para que as alterações feitas em um branch sejam revisadas e integradas ao branch principal. O pull request permite que outros membros da equipe analisem o código, façam comentários, aprovem ou solicitem ajustes antes do merge. O processo é essencial para manter a qualidade do código e a colaboração entre os desenvolvedores.



2. Qual a importância de se criar Branches em um projeto e quai as boas práticas que se deve ter ao criar uma Branch? 

Criar branches é importante porque permite isolar tarefas específicas, como o desenvolvimento de uma nova funcionalidade ou correção de um erro, sem comprometer o restante do projeto. Além disso, facilita o trabalho em equipe, pois cada desenvolvedor pode atuar em seu próprio branch, evitando conflitos e promovendo organização.
Na criação de branches deve-se usar nomes claros e padronizados que indiquem o propósito do branch; manter os branches curtos e focados em uma única tarefa para facilitar a revisão e o merge; criar branches sempre a partir da versão mais atual do branch principal; atualizar o branch com frequência para evitar conflitos; usar pull requests para garantir que o código seja revisado antes de ser integrado.
